# Contributing

This is a personal collection of Esri-related resources, kept small and utility-focused.
Contributions are genuinely welcome, and the useful ones are often smaller than people
expect.

## Start with an issue

The [issue templates](https://github.com/camrex/esri-gis-resources/issues/new/choose)
route the common cases:

- **Something returns the wrong value** — a lat/long that comes back plausible and wrong
  is the failure mode this project exists to prevent, so those reports matter most.
- **Coverage for the Arcade expression** — codes for another country, a projection method
  it does not implement, or an approach to grid-shift datums.
- **Credit** — if you wrote something this builds on, or you know who did. Named credit is
  owed and will be added.
- **A palette value** that disagrees with the ArcGIS Pro style file.

A pull request is welcome but never expected. An issue with the right numbers in it is a
complete contribution.

## The Arcade expression

**A code list is the whole contribution.** The published builds are generated, so adding
support for a country means adding its EPSG codes — not writing Arcade:

```powershell
# build_expression.py and validate.py need arcpy, so use ArcGIS Pro's Python.
# lint.py is pure Python and runs anywhere.
cd arcade-stateplane-utm-to-latlong/scripts
python build_expression.py --codes @my_codes.txt --out mine.txt
python validate.py mine.txt
python lint.py mine.txt
```

Paste what those say into the issue. Codes using an unimplemented projection method are
reported and refused rather than silently mishandled, so even a refusal list is useful.

Two rules that are easy to trip over:

- **Never hand-edit `builds/*.txt`.** They are generated by `build_expression.py` and its
  header says so. Change the template or the code list, then regenerate.
- **Run `lint.py` after any change to the template.** Arcade identifiers are
  case-insensitive, so `U` and `u` are one variable — a hazard the Node harness cannot
  see, and one that produced a real bug during development.

Parameters come from `arcpy.SpatialReference`, never from EPSG's published tables. The
two registries disagree, and the stored coordinates were made with ArcGIS's; building
from EPSG's rounded values pulls the answer up to 1 mm away from what ArcGIS would give.
[VALIDATION.md](arcade-stateplane-utm-to-latlong/VALIDATION.md) has the breakdown.

## The color palettes

Values are checked against the live **ArcGIS Colors** system style, not against Esri's
published documentation — the two have disagreed more than once. Before proposing a
change:

```powershell
python color-palettes/scripts/verify_palette.py
```

and quote the row it flags, along with your ArcGIS Pro version.

## Pull requests

Keep them scoped to one thing, note in the description which checks you ran, and update
[CHANGELOG.md](CHANGELOG.md) under `[Unreleased]`. Generated artifacts should be
regenerated by their script rather than edited. `make_palette_xlsx.py --check` and
`tools/make_social_card.py --check` report whether a committed file is stale;
`make_palette_pngs.py` simply rewrites the PNGs.
